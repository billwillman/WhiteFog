首次打开和试放

  1. 打开 E:\Tuanjie19_WhiteFog，等待团结完成脚本编译和资源导入。从菜单打开 Window → Soft Kitty → 技能工作台。已经在 Project 中选中技能图时，也可以点 Inspector 里的打开技能工作台。
  2. 首次打开时可直接看到技能库。如果窗口已有选中的技能，点顶部技能库打开列表。在「主角技能」里点御剑穿云。搜索框按技能名称筛选，清空即可恢复全部。点选后，窗口上方显示当前图的名字和摘要。
  3. 在动作时间轴点技能命中。检查开始时间 0.24、每段伤害 55、射程 16、飞行速度 19。点顶部保存。
  4. 向下滚到Demo 快速试放。默认施放方向为「主角 → 怪物」。勾选让怪物就位到主角前方，将起始距离设为 8 米。
  5. 点打开 Demo 并试放所选技能。如团结询问是否保存原场景，按项目需要保存后继续。编辑器会打开原版 URP Demo，进入 Play，等待主角与可交互的敌人生成，再施放所选技能。
  6. 观察 Game 窗口的起手提示、飞剑和命中反馈，再看工作台的施放信息及当前生命。在双方静止、无护盾、无易伤且目标血量充足时，约在 0.24 + 8÷19 ≈ 0.66 秒后扣 55 点。
  7. Play 中可直接切到另一张图，点在 Demo 试放所选技能。要保存新的设计参数，先退出 Play，再改图、保存并重试。

快速试放会自动绑定 Demo 中存活的主角和最近一只可交互怪物。第一次试放不需要手动建执行物体，也不需要把九张图分别挂到场景。

时间轴和节点怎么读

检查施放条件→战斗根节点→按各动作的开始时间执行→表现和数值结算

每行动作的开始时间以本次施放为零点。同一根节点可启动多行动作。要让第二步等到第一步完成，应填写合适的开始时间。若命中时间随距离变化，将后续扣血写在「技能命中」内，用「命中后到首段的延迟」衔接。

飞剑在途

以「星弧连闪」为例。起始距离 8 米、速度 28 米/秒。理论命中点约为 0.54、0.68、0.82 秒。团结协程按帧推进，实际时点会有帧级差异。

时间游标、横条与执行方式

点左侧动作名称，游标会对齐其开始时间。点右侧轨道，会选中该行并把游标放到点击位置。游标决定下一次「添加动作」的起点。移动已有动作时，选中它，在下方改「开始时间（秒）」并按回车。

「单次」执行一遍。「执行多次」填写次数和间隔，例如三段、间隔 0.14 秒，第一段到第三段相隔 0.28 秒。「持续执行」填写持续时间和执行间隔。行名末尾的「直接」表示连接根节点，「分支」表示经其他节点接入，「未连接」时应在节点图检查动作的执行输入。

三种样例动作

  • 施法提示指定提示对象、事件名、显示时长及施法或敌对预警类型。事件会发给所连实体。比如雷鳞震翅把预警放在受术者，御剑穿云把起剑提示放在施加者。
  • 技能命中把施加者、受术者、每段伤害作为节点输入。投射方式可选直接命中、飞剑、光弹或毒雾。射程填 0 表示不限；飞行时长取出发距离除以速度，弧线高度控制视觉轨迹。超出射程时该步骤跳过。勾选提示可显示未命中的反馈。
  • 护盾与回复选择作用实体、效果类型和数值。护盾可设持续时间，回复以该实体的 hp 为上限，写入 chp。清罡护体的两行动作都接「施加者」。

「技能命中」勾选到达时施加易伤后可编辑百分比和时长。命中后到首段的延迟用于把减益与第一段伤害分开。工作台时间轴横条表示动作的计划重复区间，投射物的在途时间根据实战距离另算。

从空白制作一招飞剑

下面做一招练习用的单体飞剑。完成后，主角会先给出施法提示，0.3 秒后出剑，在 8 米距离约 0.7 秒时命中一次，造成 30 点伤害。练习文件可以单独保存。

  1. 退出 Play，点新建技能 → 空白技能。在项目的 Assets 下选择练习目录，保存为 练习_单体飞剑.asset。工作台自动选中这张新图。
  2. 展开触发配置 → 添加必须满足的条件 → 实体存在判断。在「选择条件」中查看刚加入的节点，将实体输入选为目标。这样整招会先判断传入的目标是否存在。
  3. 在动作时间轴把游标放到 0，点添加动作 → 施法提示。设「提示对象」为施加者，「事件名」为 起剑，「提示类型」为施法，「显示时长（秒）」为 0.3。
  4. 再点添加动作 → 技能命中。选中新行，填写下表。新加的实体端口默认绑定目标，尤其要把「施加者」这一栏改为施加者。否则飞剑可能从目标身上出发。
命中动作字段本例填写值
开始时间 / 执行方式0.30 秒 / 单次
施加者 / 受术者施加者 / 目标
每段伤害 / 投射方式30 / 飞剑
射程 / 飞行速度 / 弧线高度12 米 / 20 米每秒 / 1 米。选择「飞剑」后会显示速度和高度。
超出射程时提示 / 到达时施加易伤 / 命中后到首段的延迟勾选 / 关闭 / 0 秒
  1. 点保存。在 Demo 快速试放里选「主角 → 怪物」，就位距离设为 8 米并试放。静止目标应扣 30 点。将距离拉到 15 米再试，可观察超距提示。
  2. 要制作怪物版，可先复制这张图，在编辑模式把默认施放方向改成「怪物 → 主角」。要让主角提前看到危险，将「施法提示」里的提示对象改成目标、提示类型改成敌对预警。再保存、试放，观察预警圆环所在角色和掉血方向。

已有模板也可作为起点。「单次伤害」预设为 0.1 秒时扣 30，「三段伤害」预设为每段 7、间隔 0.2 秒，「单体治疗」预设为给目标加 30。它们使用 MCC「修改属性」动作。制作带弹道或需要按生命上限回复的技能时，可分别使用「技能命中」或「护盾与回复」。

九个原生技能与 Demo 实测

下表的伤害段数与生命变化已在团结 1.9.3 编辑器的原版 URP Demo 中逐招验证。试放固定双方位置，相距 8 米，攻击前目标生命为 300，无额外增减益。主角图默认由主角施放，怪物图默认由怪物施放。正常游玩中双方可移动，其他攻击也可能改变血量。

跟做一次复制、修改和复测

  1. 在编辑模式选「星弧连闪」，点复制技能。选自己的目录，命名为 星弧连闪_测试.asset。工作台会切换到副本。
  2. 选「技能命中」行，把每段伤害从 22 改为 31，按 Enter 提交字段。执行方式仍选「执行多次」，次数 3，间隔 0.14 秒。点保存。
  3. 切去另一张图，再重新选择副本。确认显示 31。若想看底层数据，打开节点图，检查数值输入连到技能命中的对应端口，再切回工作台。
  4. 在 Demo 以 8 米试放，等三段全部结束。副本保存、重新导入后，实测从基础版的 22 × 3 = 66 变成 31 × 3 = 93，300 生命的目标剩 207。
  5. 要改成两段，修改执行次数即可。要拉开节奏，修改执行间隔。要延后整招的出剑时间，修改开始时间。三者对应不同的可见结果。

要增加表现，可把时间游标移到所需时刻，点添加动作 → 施法提示，选择作用实体、填写事件名和时长。移除动作时先选中该时间轴行，点移除当前动作。工作台支持团结编辑器的撤销操作。

Demo 快速试放与指定执行组件

快速试放现成样例

每次快速试放都会新建一个临时执行实例，交由原生 CombatDamage.DealDamage 执行当前图，结束后回收。可以连续换图和试放。勾选就位时，移动的是怪物；关闭后按场上实际位置与移动轨迹验收。

「默认施放方向」只决定 Demo 快速试放时谁作为 Dealer、谁作为 Target。图内的实体输入再决定每步具体作用于谁。例如「清罡护体」的施放方向仍可为「主角 → 怪物」，盾和治疗却都作用于主角。正式玩法由调用方传入双方。

试放自己指定的角色、执行器或武器

  1. 在「执行组件与场景试放」拖入一个 CombatDamage，或用查找使用此图的场景组件。空场景可点创建场景测试组件，它会绑定当前图并关闭自动物理检测。
  2. 在同窗展开命中检测、投射物与动态变量检查原组件设置。在「试放对象」里把带有效 EntityComponent 的施加者和目标拖到对应槽里。
  3. 进入 Play。确认执行组件使用当前这张图并完成初始化，然后点试放当前技能。手动试放通过指定目标调用图。要测试碰撞层、射线或实际命中体，请另用武器或角色的正常施法入口触发物理检测。

MCC 原版多个延迟动作复用同一个执行器时可能串目标。Demo 快速试放为每次施放分配独立实例。接入正式角色时，并行施放也应保留独立的执行上下文和足够的存活时间。

验证护盾、易伤和未命中

  • 护盾吸收。让主角先施放「清罡护体」，等 0.18 秒起效，再立刻换「雷鳞震翅」试放。后者在 0.78 秒后造成 62 点基础伤害。若两次命中之间没有其他攻击，65 点护盾吸收 62 点，主角生命不降，剩余 3 点护盾到期消失。
  • 回复封顶。记录施放前的当前生命与最大生命。例如生命 80/100，回复 28 后应为 100/100。如果 100/100 时施放，仅凭血条看不出回复，需要另验护盾吸收。
  • 易伤与取整。「缚影蚀脉」的 48 点基础伤害乘 1.35 后为 64.8，当前规则结算为 65。比较易伤结束前后的同值攻击时，要对同一个目标测量，并排除护盾影响。
  • 射程失败。先用 8 米验证「御剑穿云」正常命中，再改 20 米。射程在前摇结束时检查，实际角色仍在移动，观察当时的距离。未通过时不会发射飞剑或扣血。

九图使用生命属性 chp 和最大生命 hp。护盾和易伤同时作用于这些技能的命中及 MCC「修改属性 → 减法」对同一属性的伤害。其他游戏系统自行直接写生命时，需要按其伤害入口接入相同规则。

常见问题

技能库找不到某张图

点顶部「技能库」，清空「查找技能」。分组标题下直接列出技能。工程内 Assets/WhiteFog/Skills/ 下的图区分主角和怪物，分组由该图的「默认施放方向」决定。保存在其他目录的副本列在「其他技能图」，列表显示完整资产路径。

点了快速试放，还在等角色

确认活跃场景是 DemoScene，处于 Play，游戏未暂停，主角存活。Demo 会在运行中生成怪物，工作台会等待可交互的双方。若主角死亡，先按 Demo 提示重新开始，再点试放。

能看到特效，但伤害看起来偏少或偏多

先查射程、目标当前生命、是否存在护盾或易伤，再确认次数、间隔与在途时间。血量不足时结算会受剩余生命限制。原版 Demo 敌人会自行攻击；比对单招时应给双方足够生命，观察受术者的变化。

编辑框变灰，或节点图和工作台显示不同

先退出 Play。若节点图正在编辑同一资产，点「切回工作台编辑」。确认正在编辑原图还是副本，用路径核对同名技能。输入框按回车后再保存。

Console 出现找不到 SkillPlayback 或自定义动作

检查 Assets/SoftKitty/MasterCombatCore/Scripts/Core/SkillPlayback.cs、三个动作脚本及其 _interface.txt 是否已导入。等待脚本编译结束，从 Console 第一条红色错误开始排查。运行时反射类型同时在插件 link.xml 中登记。

如何查看更复杂的条件和公式

选中图后点「打开节点图」，从根节点的触发输入和动作输出追查连线。工作台中显示「来自节点」的端口说明它连接了公式或分支。原图使用方法见团结技能节点编辑器手册。
