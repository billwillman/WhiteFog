用技能工作台集中制作

打开独立的《MCC 技能工作台操作手册》，可在 Preview → 快速试放 选择《宗师之上》原作表现「破空剑法」（25090）。查看竖屏操作和实录。

在团结菜单选 Window → Soft Kitty → 技能工作台。也可以在 Project 面板选一张 MCC 技能图，在 Inspector 点打开技能工作台。工作台直接读写原插件的 GraphObject，能用原版节点图打开同一个文件。

  1. 用技能库搜索并打开一张图。文件路径可以区分 Demo 和核心预设中的同名技能。点复制技能制作副本，或点新建技能选择空白、单次伤害、三段伤害、单体治疗。三个数值模板已接好目标、条件和动作，默认使用 Demo 的生命属性 chp。下面从空白技能开始搭建。
  2. 展开触发配置。可直接选择已有条件改参数，或点添加必须满足的条件 → 实体存在判断。实体选「目标」，逻辑选「存在」。新增条件作为独立触发器，求值时与已有触发器共同生效。
  3. 将时间游标移到起始时刻，选添加动作 → 修改属性。在同一窗口把实体设成「目标」，属性 UID 填 chp，操作选「减法」，属性值填 7。输入框按回车提交。
  4. 选中该动作，在执行方式选「执行多次」，次数 3，间隔 0.04 秒。时间轴上每行是一项动作，横条表示计划执行区间。行首注明直接执行、分支或未连接。分支行表示可能发生的动作，实际命中由运行条件决定。
  5. 点保存。切到 Preview → 当前场景试放，可直接指定双方，或选择使用此图的伤害执行组件。空场景可点创建场景测试组件。展开命中检测、投射物与动态变量可直接使用 MCC 的原生组件面板。
  6. 填写同一场景的施加者、目标，确保两个对象都绑定有效的 EntityComponent，目标携带 chp。进入 Play 后点试放当前技能。初值 100 时，等待三段动作结束，预期生命为 79。实际团结 PC 编辑器回归得到 100 → 79。

表单中标有「共享」的实体或数值节点会同时影响该图的其他使用者。来自复杂公式的输入会标出源节点 UID；点「打开节点图」可继续改公式和分支连线。两种视图之间切换时按提示保存。

02　画布和节点

条件 / 条件组→触发器→战斗 · 根节点→动作 / 动作分支

执行路径示意。实体、变量和数学节点通过数据端口为条件及动作提供输入。

  1. 空白处右键打开创建节点菜单。选择类别和预设后，将新节点挪到有空位的地方。拖节点标题移动，滚轮缩放，中键拖动平移，空白处拖框选择多个节点。
  2. 把输出端口拖到兼容的输入端口。条件结果、实体、数值、动作各有独立语义。改节点类型后重新检查端口，尤其是原来接入的实体和数值。
  3. 删除单根线时先点选连线，再用 Delete 或右键删除。对一组相关节点执行分组，组名可用「伤害公式」「命中条件」「受击表现」。
  4. 用新建便笺写明输入、结果与例值，右键设为图摘要后可在 Inspector 里阅读。打开图后，先读摘要再看连线。
  5. 修改完点保存再进 Play。恢复回到本次打开窗口时的快照，期间点过保存也能回到开窗时的内容。关闭窗口仍会保存，需要撤回整次会话的修改时先用恢复。
节点作用常见配置
根节点组织一次求值中的触发与动作。技能计算通常保留「战斗」。根节点可连多条动作，要求严格时序的表现应显式安排时机。
触发器决定一次求值是否满足技能执行条件。同一触发器的多个「触发条件」需全部成立。需要任一成立时，先用「或」条件组归并。
条件 / 条件组读取实体或数值并输出真假。实体存在、生命值、标签、距离、高度差、角度差。条件组支持与、或、异或、或非。
实体提供被检查或被修改的对象。施加者是本次来源，目标是本次受体，玩家是全局玩家，指定按 UID 查找，执行实例关联当前执行者。
变量提供数值。常量适合调试，属性从实体读取，动态变量接受实例覆盖，随机值适合带范围的波动。
数学组合数值。倍率、加减、上下限；对减、除等运算核实输入次序。
分支根据条件结果选择执行路径或输入值。数值分支可决定暴击倍率，实体分支可选治疗对象，动作分支可切换格挡与受伤的动作。
动作改变数值或触发外部行为。修改属性、播放动画、播放音效、实例化预制体、应用持续效果、触发事件。

动作支持仅执行一次、执行多次和按时长持续执行。给多段技能标明起始延迟、间隔和次数，提交前在实际运行中数命中次数。跨技能持续状态使用持续效果资产管理更容易验收。厂商动作节点说明

03　属性与实体

先打开 Edit → Project Settings → SoftKitty → Data Settings → Data。工程已有通用设置 Assets/SoftKitty/Data/SGD_Settings.asset。查看 Data Object List 中实际启用的资产。正式技能尽量复用项目定义的 UID。练习使用 Demo 数据时，可直接用其 chp 表示当前生命值。

从空表建立一套独立的练习数据

  1. 在 Project 面板创建 Soft Kitty → Data Objects → Attribute Data 和 Entity Manager Data。进阶练习再创建 Over Time Effect Data。
  2. 在 Data Settings → Data 点击 Add 后填写资源槽，或对未分配的资产点 Assign。每类数据用一个启用的资产。同类资产已启用时，记录原来绑定的对象，需要时换成练习数据，练完恢复原配置。
  3. 在 SoftKitty → SubData - Attributes（或直接选中 AttributeObject）点 Add New [Attribute]。建数值属性 chp，显示名「当前生命」，默认值 100，关闭字符串类型。后续公式再加 atk 与 def。
  4. 在 SoftKitty → Entity Manager 点 Add New [Entity]，创建 skill_test_caster 和 skill_test_target。展开每个实体的 Attributes，下拉选到 chp 后点 Add，也可以用 Fill Attributes from Database 从表填充。确认目标的 chp 初值为 100，再保存。
  5. 需要同种怪物同时出现在场景时，在该实体模板上勾选 Multiple Instances，使各个对象拥有独立运行数据。示例用「施加者」从调用端注入，skill_test_caster 可保持普通实体。需要全局「玩家」节点时，确认项目唯一的 player 绑定。
UID练习值用法
chp测试目标 100修改属性的 UID，在项目里确认它表示当前生命。
atk测试施加者 40读取施加者攻击，给进阶公式供值。
def测试目标 15读取目标防御，给进阶公式供值。

属性表中的定义与实体实际携带的属性都要检查。节点填 UID（如 chp），弹窗里看到的显示名「当前生命」可独立修改。

04　第一张伤害图

目标是每次触发从测试靶扣 30 点当前生命值。数值是本手册的演示参数。把新图保存为 Skill_Test_Fixed30.asset。

  1. 在 Project 面板用创建 → Soft Kitty → 技能图新建资产，再双击。新图预置一个条件、一个触发器、一个根节点和一个动作，并已连好基础执行路径。
  2. 将条件的类型切到实体存在判断，逻辑选存在。检查它的输出连到触发器的触发条件，触发器连到战斗根节点。
  3. 空白处右键创建节点 → 实体 → 目标。把实体输出连到条件的实体输入。保留触发器自动重置。
  4. 将动作类型设为修改属性，执行方式选仅执行一次，延迟设为 0。属性 UID 填 chp，操作选减法。
  5. 把同一个「目标」输出连到「修改属性」的实体。添加变量 → 常量，数值设为 30，将数值输出连到动作的属性值输入。
  6. 检查根节点的动作输出仍然连着这个动作。点保存。关闭并重开一次，确认节点选择和连线写入资产。

05　进入场景验证

开始一个独立测试场景，用显式调用验证图结算。两名实体可以是普通空对象，物理检测关闭时无需碰撞体。

  1. 创建两个场景对象。选中后用 GameObject → Soft Kitty → Attach Entity Instance 绑定 EntityComponent，在 Entity UID 分别选施加者和测试目标。也可以用 Create Entity Instance 直接创建。
  2. 用 GameObject → Soft Kitty → Create Damage Object 加一个 CombatDamage 对象。Graph 拖入 Skill_Test_Fixed30.asset。启用 Enable Damage，在 Physics Detection 中关闭 Enable Physics Detection。
  3. 在 Optional References 里确认能看到 Dealer Entity 和 Target Entity。固定测试可直接绑定它们。下面的脚本通过参数传入实体，可用来验证动态锁定场景。
  4. 在自己的测试目录创建 SkillDamageProbe.cs，粘贴下面的完整脚本，挂到场景任意对象。将伤害组件、施加者和靶子拖入三个字段。进入 Play 后，在脚本组件菜单点击 Test Skill Hit。Console 查看血量前后值。
using System.Collections;
using SoftKitty;
using UnityEngine;

public class SkillDamageProbe : MonoBehaviour
{
    [SerializeField] private CombatDamage damage;
    [SerializeField] private EntityComponent caster;
    [SerializeField] private EntityComponent target;

    [ContextMenu("Test Skill Hit")]
    private void TestSkillHit()
    {
        if (!Application.isPlaying || !damage || !damage.inited || !caster || !target)
        {
            Debug.LogWarning("Enter Play and assign the initialized skill and both entities.", this);
            return;
        }

        var dealerData = caster.mData;
        var targetData = target.mData;
        if (dealerData == null || targetData == null || targetData.GetAttributeData("chp") == null)
        {
            Debug.LogWarning("Check Entity UID assignments and the target chp attribute.", this);
            return;
        }

        StartCoroutine(MeasureHit(dealerData, targetData));
    }

    private IEnumerator MeasureHit(Entity dealerData, Entity targetData)
    {
        var before = targetData.GetAttributeFloat("chp");
        damage.DealDamage(dealerData, targetData);
        // The graph schedules actions as coroutines, even with a zero delay.
        yield return new WaitForSeconds(0.1f);
        Debug.Log($"Skill hit: chp {before} -> {targetData.GetAttributeFloat("chp")}", target);
    }
}

初始化后第一击的预期为 100 → 70，第二击为 70 → 40。如果使用 Demo 中已有的实体，初始生命可能与练习表不同，应观察每击的差值。DealDamage(dealer, target) 会经过触发条件。PerformAction(hash) 会跳过触发条件，正常命中流程使用前者。厂商 CombatDamage 接口说明

这张图只验证属性变化。正式角色的死亡、血条、击退、各类受击动画及玩家输入，由对应角色系统和事件接收逻辑处理。

06　伤害公式与可调参数

复制固定伤害图，再把常量 30 替换成公式。先设一组可手算的数据，验证后再打磨倍率。

施加者 atk×动态变量 skill_multiplier−目标 def→max(1, 结果)

练习公式。40 × 1.25 − 15 = 35，满血 100 的目标结算后应为 65。

  1. 新建「施加者」与「目标」的实体输入，分别连到两张属性变量节点。UID 分别设 atk 和 def。
  2. 创建动态变量，设 UID skill_multiplier，默认值 1.25。把攻击与倍率接进乘法，再将乘积放到减法的第一个输入，防御放到第二个输入。
  3. 用最大值在公式结果与常量 1 之间取大值，输出接到修改属性的属性值。如果项目允许免疫或零伤害，按对应规则另设条件或调整下限。
  4. 保存后去 CombatDamage Inspector 展开 Dynamic Variables，确认变量 UID 与默认值对应。可为装备或技能等级覆盖组件的倍率，运行时可用 damage.SetDynamicValue("skill_multiplier", 1.5f) 后再调用结算。换 UID 后检查已有组件是否仍写入旧 UID。

继续加入暴击、护盾或格挡时，先写清它们影响的是「是否出招」「是否命中」还是「结算后的数值」。比如程序已经判定格挡，图里可以用动作分支播放格挡事件。若把格挡当成总触发失败，连接在根节点下的格挡表现也会被跳过。

07　持续伤害、增益和减益

命中技能图→持续效果动作→持续效果数据→效果结算图

命中图负责施加，效果资产保存时长、刷新和层数，结算图负责执行每次有效效果。

  1. 在 Data Settings 确认启用 OverTimeEffectObject，打开 SubData - Over Time Effect。点击 Add New [OverTimeEffect] 新建条目。
  2. 给条目一个稳定标识，填写 Duration、Can be Refreshed、Can be Extended 与 Layered / Maximum Layers。先用 4 秒、可刷新、不延长、单层练通，再决定最终叠层规则。Tick Interval 是数据资产设置，调整会影响同一数据资产的其他效果。
  3. 给条目绑定一张独立效果图。持续伤害图可先只做「目标 chp 减 5」，再通过实测确认实际的生效时点、次数与层数。参考 Demo 的 DoT_Damage 和 DoT_Frost。
  4. 在命中图加「持续效果」动作，连接目标，填效果使用的 ID。效果参数需要数值输入时，使用条目的整数 ID，对照数据库中的记录，不要填显示名。避免让效果图再次施加自身而持续刷新。
  5. 增益优先查看 Buff_Berserker 和「临时修改属性」。按项目规则验证结束后原属性是否复原、重施加是否刷新、多个来源同时施加时是否符合预期。

验收至少记录首次施加、重复施加、层数变化、自然到期、目标死亡或销毁五个时点。养成端修改的永久面板值与战斗期间的临时增益分别记录。厂商持续效果说明

练习表可先定「飞剑命中伤害 30、命中成功后播放特效、2 秒超时」。副本可扩展成怪物远程落雷和近地冲撞。落雷重点验证提示到命中的时间，冲撞重点验证横向范围和结束收招。

09　调试与排错

  1. 打开目标技能图，勾选工具栏的调试模式。如果只需要异常信息，在 Data Settings 把 Debug Level 设为 Errors Only。
  2. 进入 Play，复现一次施法。在 Console 选中此次 DealDamage() 发出的图调试 JSON。涉及延迟动作时，等待该动作结束后再查看后续日志。
  3. 复制消息里的完整 JSON 字符串，贴进图窗口的调试文本框，点调试。检查触发结果、目标 UID 和数值端口输出，从第一个异常的节点向上游查。完成后关掉调试模式，减少日志。
图能打开，按键后没有扣血

先检查技能输入是否调用了 DealDamage 或触发了物理检测。再看图是否挂到本次生成的预制体上、目标 Entity UID 能否解析、目标 AvailableForInteraction 是否有效、触发器是否通过、修改属性的 UID 是否实装。

数值正常，表现缺失

核对图中的事件名、播放动画的目标实体、Animator 参数及大小写。再看场景是否有接收处理器，特效 Prefab 与发射挂点是否存在。启用命中反馈前可用 Console 验证事件只触发一次。

直连测试通过，飞剑总是没打到

用慢速、静止目标、相同高度先验碰撞。再检查目标 Layer、实体 Tags、Collider 的 Trigger 状态和 Rigidbody 配置。在 Scene 看起点、方向和半径，确认命中点能追溯到 EntityComponent。最后提高速度并测试高低差。

同帧命中两名敌人，伤害集中到最后一个目标

当前 MCC 1.03 迁移版中，同一 CombatDamage 连续向 A、B 提交三段、每段 7 点的延迟伤害，会复用执行上下文。团结 Play 实测 A 保持 100，B 从 100 降到 58。需要独立结算的并行命中请分别使用执行实例，并让实例存活到最后一段动作完成。单实例复用前，先做这项双目标回归。

多个怪物的血量同时变化

检查它们是否指向相同实体 UID。复用同一模板时启用 Multiple Instances。检查动作连的是「目标」，而非按固定 UID 读取的「指定」。

编辑时有节点，打包后节点类型找不到

检查编译错误、命名空间和自定义节点的运行时类型。内置反射类型已经随迁移包含 link.xml，自定义反射类型也需要按目标平台做保留和验证。

技能误改，退出窗口保存了错误版本

窗口仍在本次打开会话时可用「恢复」。窗口已关闭时，从 Git 历史或手动备份找回图资产，同时检查它依赖的 UID 和数据表版本。

10　交付与验收

技能资产、使用该图的角色或飞剑预制体、实体和属性配置、事件接收脚本、动画特效等一起交接。Project 里的导出技能图可导出 .unitypackage，工具会尝试附带检测到的属性与持续效果数据。检查导出清单，并按实际引用补齐场景对象、角色逻辑与表现资源。源工程走 Git 时，将新增资产和对应 .meta 一起提交。
