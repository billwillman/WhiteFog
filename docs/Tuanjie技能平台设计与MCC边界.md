# Tuanjie 技能平台设计与 MCC 边界

适用工程为 WhiteFog，基础版本为团结 1.9.3、Master Combat Core 1.03。面向制作技能、配置 Buff 和核对战斗结果的策划。以下数值设计示例用于说明编辑方式。

## 1. 工作流与数据归属

| 对象 | 配置内容 | 复用方式 |
| --- | --- | --- |
| 技能图 | 入口事件、目标选择、执行时机、条件分支、动作和状态引用 | 同一图可交给不同角色或执行器 |
| 状态定义 | 持有者、持续时间、层数、延长、刷新、驱散、每跳参数及效果图 | 多个技能按原生数据库 ID 施加同一状态 |
| 数值公式 | 输入来源、读取时机、运算树和输出单位 | 原生图内可以共用变量及数学节点；不同状态定义还可以引用同一整张效果图 |
| 试放记录 | 施放、接触、判定、吸收和生命变动等实际事件 | 比较同一技能换施法者、目标、距离或等级后的结果 |

技能节点应能接收单位、目标组、位置、方向或事件数据。公式返回数值，效果节点才写入生命、护盾或其他资源。角色最终攻击已经包含属性系统汇总的加成，读取最终攻击后应避免重复叠加装备数值。

## 2. 主流技能模板与目标判定

| 模板 | 可拼接的流程 | 原生接入点与待补能力 |
| --- | --- | --- |
| 锁定单体／群体 | 查询或点选 → 筛选 → 排序并取目标 → 保存 → 生效时复核 | MCC 能接收 Dealer、Target。可排序、可保存并跨段分配的目标组需要扩展 |
| 方向投射／近战窗口 | 按方向发射或开启检测 → 接触事件取单位 → 筛选、去重 → 判定 → 执行效果 | CombatDamage 支持碰撞、触发、射线、扫掠、同目标冷却和命中销毁。成功命中名额及整段共享概率需扩展 |
| 地点爆发 | 选点 → 预警 → 生效时查询区域 → 对当时在场者执行 | 可利用球形、胶囊范围查询 |
| 光环／持续区域 | 建立区域 → 进入、离开或脉冲 → 对目标加减状态 → 区域结束 | 范围检测与状态可复用。多区域来源的拥有关系需要明确定义 |
| 自身／友军辅助 | 取自身或查询友军 → 立即回复／施加持续状态 | 原生属性动作与状态动作可拼接 |
| 被动／反击 | 监听事件 → 从事件取对象 → 条件、冷却 → 执行 | 原生实体事件和条件可用。需区分接触、命中、实际生命损失 |
| 召唤／放置 | 选位置 → 创建对象 → 绑定拥有者 → 独立运行和回收 | 原生创建对象动作可用。数量、阵营继承和回收策略属于项目设计 |

三把剑可以共用施放时选出的目标，也能每次发射重新选人，或等接触时取单位。选择上限、可受击关系、重复判定冷却和穿透名额各自配置。例如每把剑对每人只判一次，同时最多命中两人，应分别保存已判定名单和已命中名单。护盾全额吸收仍然可以算作命中。

~~~text
时间轴计划出剑 → 飞行／查询 → 获得候选实体 → 复核资格
  → 按技能决定是否抽命中概率 → 命中事件 → 伤害、防御及护盾结算
  → 实际生命损失事件
~~~

原九图的快速试放直接绑定双方。飞剑按距离和速度播放轨迹，时间轴标记表示预计结算机会。试放报告中应分别记录碰撞、闪避、被盾吸收和扣血；缺少运行时证据的环节只能展示为计划。

下图是可拼接的目标与判定节点设计。目标组、判定结果共享和次数预算属于待讨论的运行时能力。

~~~text
技能入口
  ├─ 锁定技 → 查询／点选 → 过滤敌我、生死与可选中性 → 排序 → 取至多 N 个候选
  │           → 保存目标组 → 各段共享、分配或重新查询
  ├─ 方向技 → 生成投射物 → 接触时取碰到的实体
  └─ 自身技 → 取得施放者 → 直接施加效果（允许跳过命中判定）

处理候选（前两路可复用）
  资格节点      复核该实体是否仍在场，阵营与免疫条件是否允许
  重复规则节点  按本投射物、本段或整次施法记录实体，可设置同一实体的间隔
  命中判定节点  决定是否需要概率；逐目标独立抽样、整段共享结果，或共享随机数再逐目标比较
    ├─ 未命中   触发落空事件，按配置决定是否消耗穿透次数
    └─ 命中     登记目标 → 触发命中事件 → 引用伤害／治疗／施加 Buff 的图
  次数预算节点  分别统计不同目标数、成功命中次数或接触次数，达到配置上限时结束检测
~~~

例如「每剑最多打两个不同敌人，打过的不再打」配置在每剑的重复规则与次数预算节点；若允许落空后再次尝试，则在命中成功时登记，若碰过就不能重试，则在接触后登记。候选上限 N、穿透上限和重复间隔的含义各自独立。

## 3. 公式树

输入可以是施法者或目标的当前属性、技能 ID 与等级对应的表行、施放时快照、状态层数、当前段或外部动态参数。节点组合加减乘除、比较、限制上下限和分支。命中率公式的输出有概率单位，判定节点负责抽样并记录结果。整段共用一次结果与共用一次随机数后逐目标比较，是两种不同配置。

~~~text
命中概率示例 → 限制在 0～100%
                └─ 施法者命中 + 等级表修正 − 此次目标闪避
伤害示例     → 角色面板攻击 × 等级倍率 × 本段占比
实际扣血     → 按项目规则计算目标减免 → 处理护盾 → 限制到剩余生命
~~~

八张攻击图的「分段命中与公式结算」动作已直接保存总伤害、命中率、防御结算三张公式的引用及本招等级表。工作台允许把任一槽复制成技能专用公式。各段独立抽样，表行或公式缺失会报告具体错误并停止执行。这里采用的倍率与结算规则均为工程样例。官方攻略提到命中和闪避影响 PVP；玩家的反推仅覆盖特定 PVP 武学直伤样本。[官方攻略](https://www.taptap.cn/moment/807375002310544041) · [玩家实测](https://www.taptap.cn/moment/816096587011853913)

## 4. 状态引用与公共生命周期

技能通过原生 OverTimeEffect 动作指定受术者、操作和状态数值 ID。数据库负责把稳定的状态 UID 映射为 ID。状态条目通过 DesignGraph 引用一张图并提供动态数值。每跳执行会传入 Dealer、Target 和当前层数 Layer。例如原生 burn 与 poison 共用效果图，但有自己的参数和叠层配置。

~~~text
施加 ─┬─ 首次 → 在受术者登记状态 ID、第一层、施加者和剩余时间
      └─ 已存在 → 允许叠层则加至上限 → 允许延长则累加时长
                  → 允许刷新且剩余时间不足时补回配置时长
有效 ─┬─ 实体公共节拍 → 执行效果图 → 递减计时 → 到期移除
      ├─ 可驱散 → 减一层 → 剩余层继续，归零移除
      └─ 强制移除 → 直接移除全部层
结束 → Remove 通知 → 由相关系统清理本状态贡献
~~~

同一受术者按状态 ID 合并。重复施加保留首次来源。满层后仍可刷新。Add、Update、Remove 是通知，Update 也会由剩余时间变化产生。当前 Demo 数据库间隔为 1 秒，由每个实体自己的时钟驱动，首次施加与首跳相位可能不同。

## 5. 五种 Buff 制作模板

| 模板 | 施加与有效期 | 叠层、刷新 | 驱散与结束 | MCC 基础与缺口 |
| --- | --- | --- | --- | --- |
| 属性增减 | 给状态持有者加攻击、减速等临时修正 | 按层重算本来源贡献，单纯续时保持数值 | 减层重算；移除最后一层时只撤销本来源 | 原生有临时属性动作和狂暴图；即时撤销指定状态实例修正要扩展 |
| 持续伤害 | 每跳读取双方和层数，计算伤害并走相应结算 | 后续跳使用新层数，刷新按公共规则 | 驱散减层；移除后停止未来的跳，已扣生命保留 | 原生灼烧与中毒可直接参考；每层独立计时、施法者分开计伤要扩展 |
| 持续治疗 | 每跳把当前生命加治疗量，限制到最大生命 | 可用动态值乘 Layer 调整每跳回复 | 减层改变未来治疗量，结束停止后续回复 | 原生变量、数学和属性动作可拼；独立首跳、单状态跳频要扩展 |
| 吸收护盾 | 施加时生成额度，受击时消费剩余额度 | 续时、补量、替换、多层独立盾量需明确选择 | 同一护盾需区分耗尽击破、被驱散和自然到期 | 原版高级伤害图有能量盾示例；多盾优先级、按实例驱散和击破回调需扩展 |
| 行为控制 | 通过免疫／抵抗资格后施加状态或限制行为 | 冰霜示例按层减速，达阈值后冻结；其他控制可设计自己的刷新方式 | 只释放本来源限制，其他控制仍生效 | 原生 Frost 图和 Demo 角色提供实例；通用沉默、打断、控制互斥及跨来源恢复需扩展 |

## 6. 工作台本版的操作路径

1. 打开 **Window → Soft Kitty → 技能工作台**，在技能页选定图。制作练习时可先复制技能。
2. 在 Buff 页查看工程当前使用的 MCC 状态库，选择状态，核对持续时间、叠层、刷新、驱散和效果图。共用整张效果图的状态各自保存动态参数。
3. 在 Buff 页选择受术者和原生操作，把状态动作添加到当前技能时间游标。需要确保「命中后才挂状态」的技能，应将动作接到已有的成功分支或接触执行入口。挂在根节点上的定时动作只能证明它到时执行。
4. 在技能页核对新增动作、实体及状态；在原生节点画布调整复杂的分支和连线。状态执行与技能动作的开始时间分别由各自的运行机制决定。
5. 公式页用于核对并编辑当前技能或 Buff 效果图中的原生数值节点。编辑共享的整张效果图会影响引用它的状态；仅修改一个状态的动态参数只影响该条定义。

| 议题 | 需要决定什么 | 影响 |

验收应覆盖两人施加同一种毒、满层续时、驱散一层、满血治疗、护盾吸收后零扣血、控制重叠后解除其中之一，以及飞剑落空。编辑器界面与已经验证的运行时能力应分别验收。

## 8. 用《宗师之上》1.3.0 校准技能模板

工程中的[游戏策划拆解](../宗师之上-游戏策划拆解.html)解释六槽、构筑与自动战斗。制作具体武学时，优先核对本机的[战斗数值与角色技能运算](<file:///E:/zszs_restore/CombatRestore_1.3.0/CombatMath/Index.html>)和[施法与命中专项分析](<file:///E:/zszs_restore/CombatRestore_1.3.0/SkillReleaseStudy/Index.html>)。前者整理了 176 个功法条目、7,386 条阶级记录；后者用主角与首领各一招核对客户端施法过程。以下数字均限该版本与相应阶级。两份专项分析存于本机工程外。

### 等级表取值的具体例子

~~~text
功法 kungfu_info.levelup_id
  → 以 (id, advance, level) 查 skill_lvlup_info
    ├─ damage[1] → 攻击倍率。这组样本用原值 ÷ 1000 得到乘数
    ├─ damage[2] → 该行第二项，保留原值和单位
    └─ skill → 本级实际释放技能 → 查 skill_info、动作及音效

破空剑法 1阶0级 → 25090，倍率 4.5，第二项 0
         1阶1级 → 25090，倍率 4.5，第二项 1600
         1阶5级 → 25091，倍率 4.725，第二项 8000
~~~

等级变化既可能换数值，也可能换技能变体。平台若要接这类表，需要同时传入功法 ID、阶与级。客户端战报能区分伤害、耗盾以及当前生命的 old/new；实际生命损失可用同一目标同一次变更的 old − new 核对。固定项参与减伤的位置、飞剑段间占比、服务端命中概率仍缺少定论。工作台现有八招可以按技能等级查表、切换公式并试算。原作的「功法 ID、阶、级 → 技能变体」是另一层映射，接入时还需要对应的养成数据。

### 五类状态怎样走完一次生命周期

~~~text
属性增减   技能施加 → 登记层数 → 公共 Tick 写临时属性 → 重施加层或续时
           → 驱散一层 → 后续 Tick 按剩余层计算 → 到期／移除
           狂暴实例中的临时修正有自己的计时。即时回收同一来源修正需要扩展。
持续伤害   命中成功出口或其他技能自定入口 → 施加灼烧 → Tick 读来源、配置值和层数
           → 伤害结算 → 重施、刷新或驱散 → 移除后停止未来各跳
持续治疗   施加 → Tick 读目标当前与最大生命 → heal × Layer → 写回封顶生命
           → 新层影响下一跳，刷新补时 → 驱散减层／移除 → 停止回复
吸收护盾   拟议实例流程：施加得到额度 → 按策略叠量或刷新 → 受击时先核对可用额度
           → 消耗后结算剩余来伤 → 耗尽、驱散或到期 → 回收本盾。原生参考为能量盾结算图。
行为控制   复核目标资格 → 施加冰霜 → 按层减速或触发冻结 → 重施或刷新
           → 减层／移除 → 由控制器解除对应限制。多来源限制的所有权需扩展。
~~~

### 跟做一张可运行的条件自疗图

1. 在「技能 → 新建技能 → 目标有状态时按攻击自疗」选择工程状态库中的一个状态，例如中毒，保存为新的技能资产。
2. 打开节点树。条件检查目标是否持有选定状态；成立才执行治疗。三个属性节点均接施加者，分别读取 atk、chp、hp。治疗写回施加者。此模板抽取的是流风回雪扇的一条条件回复路径，完整武学还包含攻击与另一条回复条件。
3. 打开「公式与数值」，选择最后的最小值节点。令施加者攻击为 50、当前生命为 80、最大生命为 100、healRatio 为 1.2，则名义治疗为 60，预期生命为 100。封顶及负治疗量钳制是本模板的项目规则。
4. 在 Demo 先对无此状态的目标试放，再给同一目标施加所选状态并试放。让施加者预先损失一些生命；对照工作台中双方生命与状态的变化。目标有状态时施加者回复，受术者的选取不跟随条件检查的对象。

~~~text
目标实体 → 有指定状态？
             ├─ 否 → 结束
             └─ 是 → 修改施加者.chp
                       └─ min(施加者.hp, 施加者.chp + max(0, 施加者.atk × healRatio))
~~~

## 10. 八张攻击图的当前实现

技能图的动作保存三张可复用的 SkillFormula 资产和一张独立 SkillLevelTable。御剑穿云原来通往伤害输入的常量已替换为技能等级输入。原版技能命中动作仍可供其他图使用。辅助技能清罡护体保持原有的护盾和回复配置。

~~~text
施放者（Dealer）与当前目标（Target）
  → 等级输入 skill.level（未指定时为 1）→ 读取本招等级行
  → 整招总伤害 = 最终 atk × level.ratio + level.flat，下限 0，施放时取一次
  → 前摇结束检查射程 → 发射或直接进入判定
  → 各段间隔依次到时
      → 命中概率 = 限制到 0～1［level.accuracy + (施法者.agi − 目标.agi) × level.agiFactor］
      ├─ 落空 → 跳过该段，后续段照常
      └─ 命中 → 本段原始伤害 = 总伤害 × 本段占比
               → 防御后伤害 = max(0, 本段原始伤害 − max(0, 目标当前 def) × 本段占比)
               → 目标易伤 → 护盾吸收 → 限制到剩余生命 → 写入当前生命
~~~

这套样例用身法差修正命中，用段占比分摊防御。默认一级倍率依据八个练习技能原有的相对强弱设置，按最终攻击 100 作为标尺。二、三级倍率分别为一级的 1.2 与 1.4 倍。它们是项目内可替换的数值配置。真实装备只需把攻击加成纳入角色最终属性；公式通过 MCC 的 Entity.GetAttributeFloat 取得面板汇总值。传入等级表示这名角色掌握该技能的等级，正式玩法可以在施放前调用 CombatDamage.SetDynamicValue("skill.level", 等级)。

共用公式位于 [攻击公式目录](../Assets/WhiteFog/Skills/攻击公式/)，各招的表在其「等级表」子目录。选中技能后，摘要下方按等级逐行显示攻击倍率、固定加值、基础命中率和身法修正，可直接改值并用顶部「保存」写回。工作台用 95 表示 95% 基础命中率，用 0.5 表示每点身法差修正 0.5 个百分点。「看公式」打开引用资产；「专用副本」复制一份并只重绑选中的公式槽。段占比以百分数填写，合计 100%。工作台的「技能编辑」与「Preview」是独立页签。Preview 共用当前技能，提供「快速试放」和「当前场景试放」。本次试放方向、距离和等级是预览设置。快速试放已经指定受术者，仍会为该目标逐段抽命中。飞行表现、是否命中及生命损失分别产生于不同阶段。

**团结 1.9.3 隔离 Demo 验收**：8 张图逐招试放，加上 7 个对照用例全部通过。御剑穿云在目标最终防御 12、无盾且命中时，攻击 100、技能 1 级扣 43；只升至 3 级扣 65；回到 1 级并从属性模块增加 40 攻击，同样扣 65。星弧连闪一次飞行后分三段；在第一段后提升目标防御，实测依次扣 10.8、4.2、7。命中率为零、超距和护盾完全吸收三个用例均为零生命损失。另核对了公式专用副本、缺少等级行、无效段占比及节点画布保存后引用仍有效。
